Short summary of what changed for ROS2 + Fortress:

It was already mostly ROS2, not ROS1: old EUFS plugins use rclcpp but target Gazebo Classic APIs (gazebo::ModelPlugin, gazebo_ros::Node, GZ_REGISTER_MODEL_PLUGIN) in gazebo_ros_race_car_model.cpp and gazebo_ground_truth_cones.cpp.
You replaced Classic model plugins with Fortress system plugins using ignition::gazebo / gz::sim (ISystemConfigure, ISystemPreUpdate, IGNITION_ADD_PLUGIN) in eufs_gz_dynamics.cpp and remastered cone plugin.
Build/deps were moved from gazebo_dev/gazebo_ros to Fortress libs (ignition-gazebo6, ignition-plugin1, ignition-math6) in remastered CMake/package files.
Plugin discovery switched from Classic GAZEBO_PLUGIN_PATH style to Fortress system plugin paths (GZ_SIM_SYSTEM_PLUGIN_PATH / IGN_GAZEBO_SYSTEM_PLUGIN_PATH) via env hooks.
Car xacro moved from libgazebo_race_car_model.so to libeufs_gz_dynamics.so, plus Fortress built-in systems for joint states/odometry in eufs_car.urdf.xacro.
Control interface was adapted to Twist /cmd_vel for the dynamics plugin, with Ackermann still supported through bridge nodes (ackermann_cmd_bridge) in sim_car.
Launch stack was modernized around ros_gz_sim + ros_gz_bridge, and world/system plugins are injected/ensured for Fortress in gazebo_sim.launch.py.

For steering_gui, the remaster changes were mostly cleanup/adaptation, not Gazebo API migration:

eufs_rqt was split down to a dedicated package steering_gui (mission-control GUI removed, only steering GUI kept).
Package/module/plugin names were renamed from eufs_rqt.* to steering_gui.* (plugin.xml, scripts, setup files).
Runtime deps were simplified (dropped eufs_msgs, added std_msgs for brake command publishing).
UI/resource paths were updated to the new package name.
Functionally, it still publishes AckermannDriveStamped, but was extended to support your extra command mode handling (throttle in addition to acceleration/velocity), matching your current control pipeline better.
So yes, with this included: dynamics + cone plugins are the Fortress port, and steering_gui is the ROS2-side control GUI refactor to fit your remastered stack.
